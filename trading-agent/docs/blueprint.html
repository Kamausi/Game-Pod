How a decision flows

The model only judges. Code owns every threshold, size, stop and side effect.

exchange feed→ state engine→ snapshot ≈100 tokens→ model: typed Decision→ policy: gates + ¼ Kelly→ risk check→ paper broker→ journal → nightly review

The slow "brain" layer (research and the nightly review) sits outside this loop. It writes proposals that a person approves. Nothing it produces is merged automatically.

The decision schema and its gates

The model returns one JSON object per bar, constrained by a strict schema and validated again in code. Any violation, timeout, refusal or error becomes a hold.

{ "regime": "trending | mean_reverting | high_vol | crisis",
  "direction": "long | short | neutral",
  "direction_confidence": 0.0–1.0,
  "p_win": 0.0–1.0,          // target before stop, 1.5×ATR stop, 2:1 target
  "toxic_flow": true | false,
  "setup_quality": 0 | 1 | 2 | 3,
  "risk_state": "safe | near_limit | reduce",
  "rationale": "one sentence, logged, never read by code" }

A trade fires only if every gate passes

  • qualitysetup_quality ≥ 2
  • confidencedirection_confidence > 0.80
  • risk_statethe model reads safe
  • flownot toxic
  • regimenot crisis
  • sidelong, unless shorts are switched on

Sizing

p = calibrate(p_win)
b = (target − costs) / (stop + costs)
f* = p − (1 − p) / b
risked = 0.25 × f* (multiplier hard-capped at 0.25)
notional = risked / (stop + costs), then clamped to 30% of equity

Limits the model can't touch

Every order goes through one guarded path that runs these checks first. Closing a position is always allowed. Flipping a position counts as new risk.

Drawdown from peak15%, can't be raisedLatches the kill switch. It survives restarts and clears only by hand.

Decision engines

  • rules (default): a deterministic trend and volatility baseline, free and offline. It is the benchmark any model has to beat, not a claim of edge.
  • claude: Claude Haiku 5.5 on every bar (low effort, 10 s timeout). It hands off to Claude Opus 5.5 (high effort) when a directional call has confidence under 0.60 or the read is crisis. Hand-offs are limited to one per 5 minutes; past that, the bar is a hold.
  • Any other model plugs in as a class with name and decide(snapshot).

The nightly review

  1. Score each directional call: did price reach the target before the stop within 24 bars?
  2. Compare Brier scores for raw probabilities, calibrated ones, and a constant base rate. Raw has to beat the base rate.
  3. Refit the calibration curve, which the loop loads on its next start.
  4. Write review.md with proposals. Thresholds, limits and the prompt never change automatically.
  5. Optionally run prompts/nightly_review.md in Claude Code: one change, on a branch, with a test, for you to merge or reject.

3,000 simulated hourly bars with no pattern to find, starting from $10,000.

The review then said: "Model p_win is no better than the base rate. Do not go live." That is the correct outcome. With no edge, the system loses roughly its costs, risk stays bounded, and the review catches it. A big profit on this data would mean a bug.

Launch gates, in order

  1. Tests pass, and a backtest on real candles beats buy-and-hold on a risk-adjusted basis after fees, across at least 3 separate periods.
  2. At least 30 days of paper trading with no unexplained failsafe bursts and no risk-layer bugs.
  3. At least 200 resolved calls, with raw Brier clearly below base-rate Brier (by 0.01 or more).
  4. Paper P&L is positive after fees, and drawdown stayed under 10%.
  5. Only then write a live broker, routed through the same guarded path. Use a trade-only API key with no withdrawal rights and an IP allowlist, and an amount you can lose entirely.

What could I be wrong about?

There may be no edge at all

Classifying BTC bar by bar from 18 numbers is a crowded game. The likeliest outcome is losing about the fees. Paper trading finds that out cheaply.

Costs could dominate

6 bps fee and 2 bps slippage per side, plus spread, is a real share of each target on hourly bars. Your fee tier matters more than any prompt.

Model probabilities aren't calibrated

Self-reported confidence clusters on round numbers and drifts between model versions. Reset the calibrator after any model upgrade.

Stops are checked by polling

Every 15 s live, and on bar high/low in the backtest. Gaps and outages can skip past a stop, and a large gap can push drawdown beyond 15%.

The data feed hasn't run against the real API

The build environment blocked the exchange. Run tradebot status --probe first.

Outcome labels are coarse

The review uses mid prices at decision times, not full tick paths, so it undercounts stop touches between bars.

The regime read is thin

One venue and 50 daily bars. It's a sketch, not a macro view.

Nightly tuning can fit noise

That's why it's one change per night, a 7-day test window, and nothing goes live the night it was made.

AgenKit and Jev might be real

If they are, this page undersells them. The design doesn't depend on either.

Start here first

Run these from the trading-agent folder. Steps 1 and 2 need no network or keys.

# 1. Run the tests
PYTHONPATH=src python3 -m unittest discover -s tests

# 2. Full pipeline on simulated data, then the review
PYTHONPATH=src python3 -m tradebot backtest --synthetic 3000 --run-dir runs/bt
PYTHONPATH=src python3 -m tradebot review --run-dir runs/bt

# 3. Check the exchange feed from your machine
PYTHONPATH=src python3 -m tradebot status --probe

# 4. Paper trade 24/7 with the free rules engine (run under tmux or systemd)
PYTHONPATH=src python3 -m tradebot paper --instrument BTC_USD --timeframe 1h --engine rules

# 5. Optional: the Claude engine (API cost on every bar)
pip install anthropic && export ANTHROPIC_API_KEY=...
PYTHONPATH=src python3 -m tradebot paper --engine claude --run-dir runs/paper-claude

# Stop trading instantly (closing positions is still allowed)
PYTHONPATH=src python3 -m tradebot kill --run-dir runs/paper

Run the rules and Claude engines side by side on paper for 30 days. If Claude doesn't beat the free baseline after fees, you've learned that without risking any capital.
